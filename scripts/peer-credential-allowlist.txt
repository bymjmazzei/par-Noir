# Burn-down list for the owner-only-credentials rule
# (diagnostic-discipline.mdc section 4).
#
# A route may only act on the cloud of the pn it authenticated. Building a Drive
# token off a stored credentials row is how every cross-user write got made, and
# under device cloud custody those rows are stripped shells, so those writes fail
# — usually silently. resolveOwnerDriveToken() is the only sanctioned path,
# because it prefers the caller's forwarded X-PN-Cloud-Access-Token.
#
# Entries are only ever REMOVED, never added.
#
# REMAINING: 1 file, and it is not a peer write.
#
# identityMigrationService resolves the PREDECESSOR identity of the same human
# during a pn rotation, not another user. It is still dead under custody for the
# same reason (the predecessor's row is stripped), so migration has to move to a
# device-driven flow where the client unseals both vaults and forwards a token.
# That is a separate piece of work from eliminating cross-user access.
#
# One path per line, relative to repo root. Blank lines and # comments ignored.
